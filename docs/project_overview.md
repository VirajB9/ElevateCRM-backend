# Project Overview: Digital Marketing Agency (DMA) ERP Backend

This document provides a comprehensive overview of the **DMA CRM Backend**, generated by analyzing the project's codebase topology using `codegraph-dma` and `graphify` MCP servers.

## 📊 System Architecture & Tech Stack

- **Language & Framework**: Java 17 + Spring Boot 3.5.15
- **Database**: MongoDB (Localhost:27017, DB: `digital_marketing_agency`)
- **Security**: Spring Security with JWT (jjwt) + BCrypt Password Encoding
- **Architecture Pattern**: Feature-based Packaging (Domain-Driven Design influenced).
- **Control Flow**: Controller ➔ Service ➔ Repository ➔ MongoDB Document
- **Data Transfer**: Controllers never expose entities; everything is strictly managed through DTOs.

## 🧩 Core Modules & Domain Model

Based on our graph queries, the system is fully modularized with 5 core domains serving as the backbone of the agency's operations:

### 1. **Auth & User Module**
- **Central Node**: `User`, `Role`, `PermissionType`
- **Responsibilities**: Manages the multi-tiered RBAC system (Owner > Manager > Employee). Features JWT-based login, stateless sessions, and fine-grained permissions via `module:action` constraints.
- **Key Components**: `AuthController`, `AuthServiceImpl`, `UserRepository`.

### 2. **Lead Module**
- **Central Node**: `Lead`
- **Responsibilities**: Handles the top of the sales funnel. Leads can be created, searched, and updated based on status (`LeadStatus`) and source (`LeadSource`).
- **Key Workflows**: Contains strict duplication validation (via email/phone) and supports an atomic `convertLeadToClient` workflow.

### 3. **Client Module**
- **Central Node**: `Client`
- **Responsibilities**: Once a Lead is converted, it becomes a Client. This module manages ongoing relationships, company profiles, and client health metrics.
- **Key Workflows**: Provides 360-degree views, filtering clients by status (Active, Paused, Churned), and linking multiple points of contact.

### 4. **Project Module**
- **Central Node**: `Project`
- **Responsibilities**: Represents a deliverable or campaign tied to a specific `Client`.
- **Key Workflows**: Tracks deadlines, budget utilization, and campaign statuses. Projects can be searched and grouped per client.

### 5. **Invoice Module**
- **Central Node**: `Invoice`
- **Responsibilities**: The financial engine. Maps line items, calculates taxes, and ties back to both `Client` and `Project`.
- **Key Workflows**: Features robust state-machine logic for invoice status (Draft, Unpaid, Paid, Overdue).

## 🕸️ Codebase Topology (Graph Insights)

From our graph analysis, we identified the "God Nodes" (the most heavily referenced components in the codebase), which highlight the strict design patterns enforced:

1. **`BadRequestException`**: The most connected node! This indicates a highly defensive programming style where input validation and business logic constraints are strictly enforced across all 5 modules.
2. **`User` & `Role`**: Deeply integrated across all services (e.g., auditing `assignedUserId` on Leads, or `createdBy` on Projects).
3. **Response DTOs (`InvoiceResponse`, `ProjectResponse`)**: Proves the architectural rule: *Entities are never exposed*. Mappers heavily rely on these DTOs to serialize data back to the client.
4. **`BaseEntity`**: Inherited by `Lead`, `Client`, `Project`, etc., ensuring consistent audit trails (createdAt, updatedAt) via Spring Data MongoDB annotations.
